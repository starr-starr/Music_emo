# Music_emo 核心项目完成计划

> **文档目的：** 定义“完成 Music_emo 核心部分”的可执行开发范围、顺序和验收条件。它服务于代码开发，不包含社区运营、正式发布、后端建设或版权内容运营。

## 1. 产品完成定义

Music_emo 完成的目标不是复刻或替代任何音乐服务，而是成为一个**可独立开发和演示的音乐发现前端**。在开发者配置的兼容 API 或内置 mock 数据可用时，用户应能完成以下闭环：

1. 打开应用，看到推荐内容或明确的加载/失败提示。
2. 浏览推荐、歌单、榜单、新碟、歌手和电台这六类发现内容。
3. 从推荐卡片、榜单歌曲或详情列表中选择歌曲。
4. 在底部播放器中播放、暂停、上一首、下一首、切换顺序/随机/单曲模式、拖动进度，并查看同步歌词或“暂无歌词”。
5. 当 API、图片、音频或浏览器自动播放策略失效时，页面不崩溃，并给出下一步可执行提示。

### 1.1 核心范围

- 发现内容：推荐、歌单、榜单、新碟、歌手、电台。
- 播放体验：播放队列、媒体状态、歌词状态和失败恢复。
- 可复现开发：一键使用 mock 或明确配置兼容 API。
- 工程质量：类型、测试、构建、lint、性能和安全基础。

### 1.2 明确不属于本期核心

- 登录、注册、用户收藏、社交/好友、个人音乐库和下载功能。
- 服务端、账号、支付、版权授权、音乐文件托管、搜索索引和推荐算法。
- 任何绕过第三方服务认证、订阅、版权、接口限制或使用条款的功能。
- 新的 AI Agent、CLI、插件、自动执行或 OpenAI API 功能。
- 全量视觉重做、移动端原生应用和国际化。

当前 `/my`、`/friends`、`/download` 等并非核心能力。它们应在本期内从主导航隐藏，或统一替换为说明明确的“暂不支持”页面，不能保留无功能占位页或失效链接。

## 3. 架构决定（必须先确定）

### D1：数据源采用 mock-first、compatible-API 可选模式

- 默认开发模式使用仓库内的 mock 数据，不依赖第三方音乐服务。
- 使用环境变量选择 mock 或兼容 API；`VITE_*` 中不得保存密钥或 bearer token。
- mock 只使用项目有权使用的演示元数据和资源；不内置受限制的音频内容。
- 兼容 API 的请求路径、响应字段、错误行为和速率限制假设记录为一个 API contract。

**验收：** 断开网络后，以 mock 模式运行仍能完成核心发现和播放器 UI 流程。

### D2：以领域模型作为组件边界

定义并集中导出 `Song`、`Artist`、`Album`、`Playlist`、`Ranking`、`Banner`、`LyricLine`、`ApiError` 等模型。外部 API DTO 只允许存在于 `src/services` 或 `src/api` 中，并在进入 store 前进行转换。

**验收：** 业务组件、Redux state 和播放器不再包含 `any` 形式的远程数据。

### D3：播放器以状态而非隐式副作用驱动

播放器至少区分 `idle`、`loading`、`ready`、`playing`、`paused`、`blocked`、`error`；歌曲、歌词和音频可分别失败。歌曲选择不能在 `App` 的每次渲染中重复请求。

**验收：** 无有效歌曲、歌曲 URL 失败、浏览器拒绝自动播放、歌词缺失、队列为空时均有确定状态和 UI 反馈。

### D4：桌面优先，保证基本可访问性

保留现有桌面视觉方向，不做重新设计；核心交互按钮需要可见文本或 `aria-label`，图片有有意义的 `alt`，播放器可通过键盘操作，焦点状态可见。

**验收：** 键盘可操作播放/暂停、上一首/下一首和进度条；没有空 `href` 或以普通锚点伪装的应用内路由。

## 4. UI 重设计任务：Music_emo 的独立音乐体验

### 4.1 设计目标与参考边界

本项目参考 Apple Music Web 的**内容优先、清晰导航、迷你播放器到沉浸式播放页、歌词与队列并列呈现**的产品组织方式，也参考成熟音乐产品通过 design token 统一颜色、排版、间距、动效和可访问性的做法。

参考只用于理解信息层级和交互问题，**不复制** Apple Music、网易云音乐或任何第三方的名称、图标、插画、截图、布局细节、字体资源、专有动效或品牌色。新的界面以 `Music_emo` 的独立品牌和合法的自有/占位内容呈现。

### 4.2 目标视觉方向

| 维度 | 设计决定 |
| --- | --- |
| 气质 | 克制、沉浸、内容主导；减少当前密集边框、雪碧图按钮、固定红色顶栏和“门户页”式堆叠。 |
| 颜色 | 建立浅色与深色两套语义 token：中性背景、清晰文字层级、一个独立的紫蓝/暖珊瑚强调色；封面色只能作为局部氛围，不承担文字可读性。 |
| 排版 | 使用系统字体栈和中文回退字体；标题、分区标题、元数据和辅助文字为四级层次，避免多种任意字号。 |
| 布局 | 桌面端采用可折叠左侧导航、主内容画布和固定迷你播放器；窄屏改为顶部工具栏、横向内容区与底部导航/播放器，不保留固定 980px 宽度。 |
| 内容 | 首屏由“继续聆听/最近播放”“编辑推荐”“新发现”“榜单”组成；没有个性化数据时以明确的演示内容替代，不伪称算法推荐。 |
| 卡片 | 建立统一的封面卡、横向歌曲行、榜单行、实体页头和空状态；hover 只显示与当前内容相关的播放/更多操作。 |
| 播放 | 迷你播放器显示封面、曲目信息、进度和主要控制；展开页包含大封面、歌词/队列切换和完整控制。 |
| 动效 | 仅用于状态转场、播放反馈和层级展开；遵从 `prefers-reduced-motion`，不使用持续闪烁、无意义视差或自动大幅移动。 |
| 可访问性 | 默认文字和图标满足 WCAG AA 对比度目标；功能不能只依赖颜色；支持键盘、焦点、读屏标签和 200% 缩放。 |

### 4.3 信息架构与核心屏幕

#### A. App shell

- **左侧导航（桌面）**：主页、浏览、榜单、歌手、电台；底部只保留设置/主题等本期实际实现的功能。
- **顶部工具栏**：页面标题、可选搜索入口、主题切换和当前 API/mock 状态；未实现搜索时不展示可输入但无结果的搜索框。
- **全局迷你播放器**：固定于安全区域上方；播放状态、队列数量与错误状态在这里可见。
- **非核心路由**：`/my`、`/friends`、`/download` 不伪装成可用功能，改为统一的说明页或从导航移除。

#### B. 首页与发现页

- 首屏 hero 使用合法封面或纯 CSS 渐变背景，配一个明确的主行动按钮；不使用第三方品牌横幅。
- “继续聆听”由本地最近播放队列驱动；首次使用时显示轻量空状态。
- 推荐、新碟、歌单和歌手使用可响应的网格；榜单使用密度更高的歌曲行，避免所有内容重复使用同一种卡片。
- 每个模块必须具有 loading skeleton、empty、error 和 retry 的视觉规范。

#### C. 实体页与详情页

- 歌单、榜单、专辑和歌手采用统一的实体页头：封面、名称、辅助信息、播放全部/播放按钮和歌曲列表。
- 歌曲行支持播放、加入队列和可访问的更多操作；长标题、缺封面、缺作者均有降级样式。
- 电台页是频道卡与节目列表，不实现订阅或付费流程。

#### D. 播放器与歌词

- 迷你播放器可展开成沉浸式播放层；展开层使用应用 token 与封面氛围色，不使用 Apple 或第三方视觉资源。
- 桌面宽屏中歌词/队列可作为侧栏切换；窄屏中使用底部抽屉或独立页面，避免内容拥挤。
- 当前歌词、播放模式、音频加载/失败和自动播放受阻必须有文字与图标反馈，不能只改变颜色。

## 6. 核心验收场景

每个场景必须可在 mock 模式下自动化或手工稳定复现：

1. **首次打开：** 推荐页显示内容；请求延迟时显示 loading；失败时有 retry。
2. **浏览发现：** 从推荐进入歌单、榜单、新碟、歌手、电台；没有空白占位页或死链接。
3. **选择歌曲：** 在榜单或详情中点击歌曲，队列更新，播放器显示正确歌名、歌手、封面和加载状态。
4. **播放控制：** 播放/暂停、前后切歌、三种播放模式和进度拖动的结果正确。
5. **媒体失败：** 音频 404、自动播放被拦截、无歌词、歌词服务失败时，用户可继续选歌或重试。
6. **异常数据：** 缺少封面、作者、时长或歌曲字段时，UI 显示降级内容且控制台没有未处理异常。
7. **质量门：** 新环境依次运行 `npm ci`、`npm test`、`npm run lint`、`npm run build` 全部通过。
8. **界面体验：** 在 1440px、1024px、768px、375px 下，导航、首页、实体页和播放器均无横向溢出、死链接或遮挡；浅/深主题和 reduced-motion 模式可用。
9. **可访问性：** 仅用键盘可完成浏览、选歌和播放控制；图片、图标按钮、错误与状态变化有可读名称或文本提示。

## 7. Definition of Done

只有同时满足下列条件，才称为“核心项目完成”：

- 阶段 A、B、C 的任务和 UX1-UX9 均完成，阶段 D 的 D1-D4 完成。
- 六类发现内容和播放器闭环在 mock 模式下可用；兼容 API 模式的失败行为可预期。
- 没有可见的无功能占位页、空链接、硬编码 API 路径或由 `App` 重复触发的初始歌曲请求。
- TypeScript、lint、测试和生产构建全部通过。
- 未提交密钥；外部网络、token、媒体和第三方资源的边界已记录且在代码中受限。
- 本期非目标没有被以“临时功能”形式混入核心路径。
- 新 UI 在规定视口、浅/深主题、键盘操作、200% 缩放和 reduced-motion 模式下通过验收；不含第三方品牌视觉资产或模仿性界面。

## 8. 执行规则

- 每个提交只关联一个或少数相邻任务 ID，例如 `feat(player): complete C2 media states`。
- 每一阶段开始前先补测试或定义验收样例；不得以视觉效果替代功能验收。
- 兼容外部 API 的改动必须同时更新 contract 与 mock；不得只在个人本地服务上验证。
- 对第三方资源、音频和品牌素材只做降级与边界处理，不假设拥有再分发或播放权。
- 出现与本期非目标相关的需求时，记录为后续决策，不扩展当前实现范围。
- UI 改动先更新 token/组件规范，再组合页面；禁止在页面中继续散落不可复用的任意颜色、像素尺寸和雪碧图定位。
- 每个视觉任务至少提供一个关键状态（默认、hover/focus、loading、empty 或 error）及一个窄屏验收截图。
