# Security policy

## Supported versions

Security fixes are assessed for the current `master` branch. This is a learning project and no compatibility or response-time guarantee is made.

## Reporting a vulnerability

Please do not include exploit code, credentials, personal data, or full vulnerability details in a public issue.

1. If the repository's **Security** tab offers private vulnerability reporting, submit the report there.
2. Otherwise, open a public issue containing only the affected version, a high-level impact summary, and the text `Security report — details withheld`.
3. The maintainer will reply with a private contact method before requesting sensitive details.

Reports should include affected paths, safe reproduction steps, expected versus actual behavior, and potential impact. Please allow a reasonable time for assessment before public disclosure.
